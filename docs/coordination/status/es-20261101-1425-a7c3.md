## Implemented callable behavior

`living_damage::hurt<H: LivingDamageHost>(&mut H, &H::Source, f32)` ports actual
LivingEntity.hurt gates, shield/equipment callbacks before cooldown rejection,
full/delta hit state order, causing/direct attribution, damage/status/impact
ordering, knockback, lethal totem/death dispatch, source/time, effects and
criteria. Its trait owns no health, alive flag, timer, identity or RNG.

`player_damage::{server_player_hurt, hurt, actually_hurt}` port the distinct
ServerPlayer spawn/PvP/causing-arrow gates, Player ability/difficulty/shoulder
callbacks, and armor/magic -> canonical absorption/stat -> exhaustion/combat ->
canonical health/stat/game-event sequence. Parent dispatch and every side effect
are mandatory fallible host callbacks. Source identity is retained throughout.

`combat::reduction::{get_damage_after_armor_absorb,
get_damage_after_magic_absorb}` reuse existing survival formulas behind real
tag/equipment/attribute/weapon/effect/enchantment/statistic callbacks. Armor
breaks precede attribute reads. DIRECT source entity supplies the weapon;
CAUSING entity supplies dealt-damage statistics. Resistance and enchantment
bypasses execute at the source locations, preserving Java branch semantics.

`combat::totem::check_totem_death_protection` ports main/offhand scan, canonical
stack copy before shrink, player stat/criterion/game event, health restoration,
effect removal/addition and event 35. It does not invent an inventory/effect
owner, return a consumed item on a later error or skip mandatory callbacks.

All errors preserve the completed mutation prefix. A successful delegated
callback must mean the actual owner ran it; no callback has a no-op default.
These cores contribute partial survival_combat.2/.3 and effect-related behavior.
No entire damage/death/respawn, entity, mob or survival delivery is complete.
