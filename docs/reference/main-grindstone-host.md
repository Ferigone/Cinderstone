# Native grindstone Host transaction

`src/main_grindstone.rs` supplies the integration-side implementation of the
actual generic `GrindstoneMenuHost` contract. The stations integration branch
is composing its real Main exports/calls. No compiler/runtime production proof
or aggregate completion is claimed by this source ledger.

The retained original menu is never reconstructed from equal stacks or a fresh
menu. The transaction uses the genuine same-token `staged_copy_for_host`
API delivered by the kernel owner in PR76, preserving its actual binding,
registry, token, cursor, drag state and revision. It creates no fresh identity.

The binding contains actual actor ID/UUID, the actual transient Level owner's
address under the server's world lock, dimension and captured block position.
The kernel's own instance/revision token and the immutable configured
registry/tag/feature snapshot additionally participate in every stage. The
address is neither dereferenced nor persisted or treated as a world seed.

The native Host stages a clone of the actual canonical `PlayerContainer`, its
real player/Level RNGs, source-preserving shared index preparation, the actual
XP runtime proposal and ordered source events. `begin_stage` privately copies
these proposals, including the index's real generation/section encounter order.
`publish_stage` validates the captured owner and installs the enclosing
proposal. Only the final `SharedContainer` transaction can prepare/consume the
actual mixed Item/XP registration token and install the retained menu. Any
fallible preflight failure before that point retains every actual original.

Each source drop runs the actual item constructor and advances the staged
player/Level streams immediately, registers its proposed real index position,
and records its statistic checkpoint after the matching world-add. Each XP
award immediately advances the actual XP proposal, merge candidates, shared
index, ID sequence and Level stream. Consequently later quick-move takes see
earlier orb merge draws and earlier new orbs. Amounts are never deferred to an
end-of-click replay or converted into a floating furnace recipe reward.

The actual mixed batch prevalidates the complete addition order. Its Before /
Registered / Complete callbacks interleave real Item publication, actual XP
handle attachment/checkpoint publication, menu packets, canonical inventory
dirty-counter calls, actual inventory criterion observations and level1042.
Existing orb merges without new registrations still commit at their exact
source award event. There is one item outbox, one XP owner, one index and one
shared entity-ID allocator.

Close publishes its actual CloseScreen first when requested, then cursor/input
returns or drops in source order. The actual `Inventory.add` and
`placeItemBackInInventory(...,true)` implementations are reused; no derived
result becomes an owned drop. Local listeners retain their own source phases;
the admitted empty-criteria/nonreentrant context is checked before mutation.
The kernel already executes the constructor-default input listener's two
broadcast/recompute phases. The Host does not invent another dirty counter or
rerun those notifications.

The bounded path uses the existing actual alive native creative/body profile,
real block/reach access, native callback-world/chunk/rain facts and configured
default enchantment registry. Multi-slot quick-craft rejects the unresolved
original Slot-identity HashSet order. Spectator clicks and explicit refusal
recovery use the genuine retained `broadcast_full_state` transaction delivered
by PR76; initialize/fake clicks/incremental sends are not substituted. Unknown
component identity and custom/reentrant callbacks
remain explicit pre-mutation errors.

The real provider closes only a prior external current menu, uses the shared
window allocator and stages OpenScreen before source initialization. Wrong-
window clicks while Grindstone is current are consumed/ignored, never routed
to inactive window0. Click/refusal recovery retires only the typed unsupported
reach profile through the actual captured menu's ordered close, using real
connected health/removal facts for return versus drop context.

Immediate pickup uses a synchronization-only Host bound to the retained actual
binding, registry and supplied canonical inventory. It permits only the real
Broadcast action. Unused gameplay operations have no fake world/RNG/XP/time
values; methods outside that verified source capability fail explicitly.
The actual `MainGameplayFrame` consumes its phase listeners before the retained
same-token menu comparison baselines are installed.

Main fields/exports, provider and lifecycle dispatch, whole-stage compiler and
runtime validation, publication and deployment remain coordinator-owned. This
file alone does not establish those paths.
