# Selected and creative drop host contract

`PlayerContainer::drop_selected(all)` models the unchanged original `ServerPlayer.drop(boolean)` inventory/menu stage for window0. It removes one selected item for Q or the full selected count for CtrlQ, updates the selected remote prediction, and returns nonempty drop intents with `around=false, trace_item=true`. It sends no immediate packet and does not advance the state ID. A later `broadcast_changes()` can send unrelated pending changes; the already predicted selected removal is not acknowledged again. Empty selected stacks still refresh the remote prediction, then produce no item intent. Original Java calls the final drop method for EMPTY too; that method creates no entity.

The original oracle executes ServerPlayer/Inventory removal, menu slot lookup/setRemoteSlot, menu broadcast and the original ServerPlayer synchronizer. Only world/server services, the network sink and final item creation are controlled. It captures both selected inventory and remote values inside the final drop callback, proving prediction occurs first. The native proof compares every slot, remote slot, cursor, state ID, drop flags and deferred packet bytes after each operation.

`CreativeDropGate` belongs to the connection, matching the listener's `dropSpamTickCount`; changing or closing a menu does not reset it. The host checks creative mode and the stack's enabled features, and performs block-entity coordinate replacement, before calling `allow_negative_slot_drop(slot, stack)`. Positive assignments use their existing separate path. Any negative signed 16-bit slot qualifies. An empty stack or a count at most the effective maximum can pass only while the counter is below 200. Passing increments by 20 before the host drop attempt. EMPTY attempts consume the same 20 points but create no entity. The original wrapper again uses `around=false, trace_item=true`.

Call `tick()` once at the listener's actual tick point. It decrements positive counters by one; zero and negative values stay unchanged. A counter 199 becomes 219 after an accepted attempt, then needs 20 ticks to permit another attempt. Empty stacks remain enabled even in the controlled original world with no feature flags; nonempty disabled stacks do not reach the gate.

The pinned original corpus contains 226 selected-drop scenes/1,096 operations and 820 creative scenes/3,282 operations. It includes all selected hotbar positions, Q/CtrlQ/EMPTY sequences, pending remote changes, exact 15-bit synchronization state wrap, slot boundaries, count limits and spam boundaries. Reproduce using `python3 tools/selected_drop_check.py --regenerate --release`.

Actual ItemEntity creation, trajectory, gameplay callbacks, non-window0 menus, block-entity replacement and live dispatch/tick integration remain host responsibilities. This proof does not establish those larger runtime paths.
