# ItemStack stream normalization

The reference is the unchanged Minecraft Java 1.21 `cuq.h` optional ItemStack stream codec, using an original `RegistryFriendlyByteBuf` and original registry objects. The normalization oracle does not use `ItemStack.CODEC` or rewrite Minecraft methods. The original jar SHA256 is recorded in both oracle and native evidence.

`ItemStack::normalize_patch()` removes an addition only when its payload is byte-identical to the corresponding prototype and the original decoded Java value was proved equal to that prototype. The compact policy contains 8,310 such item/component pairs. It retains four byte-identical FoodProperties overrides whose nested conversion ItemStack has Java object identity: mushroom stew, rabbit stew, beetroot soup and suspicious stew. Removing a component absent from the original item's prototype also disappears from the patch. Decode preserves the original first-entry order and applies the last duplicate addition/removal value. Encode applies the same bounded normalization to directly constructed native stacks.

The archived first checkpoint strict native comparison covers 8,840 original inputs: all 8,314 nonair prototype overrides, 513 removals, 12 ordering cases and the redundant ender-pearl max-stack-size regression. The legacy duplicate/removal unit regression also has original canonical wire in a separate reproducible fixture. Old assertions that a default rarity override or an absent removal survives roundtrip have been replaced with the original canonical bytes.

The archived first checkpoint corpus contains 9,145 inputs. That checkpoint matched 9,061 and explicitly reports 84 differences: 30 in the independent 117-vector corpus, 45 related duplicate-component cases, five nested Slots, two signed-zero NBT values and two literal text components. This is a bounded prototype/patch result, not full stream-codec compatibility.

The original independent corpus establishes that 93 of its 117 Slots are valid exact streams, one instrument vector is only a valid prefix (33 consumed bytes, 17 remaining), and 23 are rejected by original component constructors. The structural Node-schema test remains useful for schema coverage, but its acceptance is not evidence that Java accepts every value.

Next constructor work must preserve raw NBT numeric bits and Java UTF16 strings. Network NBT uses `Tag::encode_network_anonymous`, which preserves NaN payloads while normalizing signed zero. Food and potion effect constructors consume hidden chains recursively; their encoder-facing defensive copies discard those hidden chains. Nested Slot normalization must preserve list length, including trailing empty container slots. Instrument uses VarInt use duration and float range with no description NBT. Pot decorations emit exactly four positions padded with brick. Unit component 19 accepts a non-null compound, then emits an empty compound; arbitrary NBT root types must not be converted silently.

The constructor stage closes those 84 differences. `evidence/inventory-normalization-constructor-conformance.json` compares all 9,145 old inputs without differences, 445 new exact constructor streams, seven semantically equal inline trim maps, 46 primitive prototype-equality streams and 21 original map-equality pairs. Debug and release each pass 19 tests. The 117 old Node vectors now assert original Java acceptance and canonical bytes: 93 exact successes, one prefix-only instrument and 23 constructor rejections.

The seven trim byte differences are retained explicitly. Original `Object2ObjectOpenHashMap` keys use `Holder.Reference` identity hashes. Two additional identity-hash allocations can change the original output order for the same map. Original trim, material and map equality agree for all 21 independently decoded input/reference pairs. Native semantic equality ignores map order; native output is not sorted to imitate one JVM.

`ItemStack` retains raw component payloads so encoder-facing Food/Potion copies do not destroy decoded hidden-effect or identity information before prototype equality. The fallible `encode_canonical()` applies typed wire normalization. The existing `encode()` keeps its API and legacy fallback for unchecked native struct payloads. Default stacks without patches use the direct fast path.

Reproduce the constructor stage with `python3 tools/inventory_normalization_constructor_check.py --release`; add `--regenerate` to rerun its three separate original Java proofs. The first checkpoint report remains immutable at `evidence/inventory-normalization-conformance.json`. The legacy prototype checker now writes a separate `evidence/inventory-normalization-prototype-replay.json` instead of overwriting that checkpoint.

This does not prove all values of all 57 component constructors. Rich text, filtered book pages, arbitrary identity-sensitive graphs, complex nonidentical prototype representations, general CompoundTag map ordering, exact failure messages/consumption and custom datapack registries remain outside the established scope.
